你正在 Kimi Claw 提供的 Linux Terminal 内，通过 Kimi Code 的 kimi -p 运行。本模式已经是 Auto；不要建议或尝试叠加 --auto、--yolo 或 --plan。

Kimi Code 的 Bash 工具没有可用于输入 sudo 密码的交互式 stdin。因此本任务只支持当前为 root，或 sudo -n true 已成功的环境。不得询问密码，不得把密码写入命令、文件、Prompt 或日志。

从当前进程环境读取 ADMIN_USER 和 NODE_NAME。两项缺失、为空、仍含 CHANGE_ME，或不符合安全格式时，立即停止且不改系统。ADMIN_USER 只允许安全的 Linux 用户名；NODE_NAME 只允许小写字母、数字和连字符。最终摘要不得回显实际值。

目标：非交互、幂等地辅助完成 Kimi Claw 主机内部的 Tailscale SSH 配置。Tailscale 网页授权、Tailnet Policy、第二台设备真实 SSH、公网 TCP 22 负向测试和重启复测全部为 manual-required。不能把服务器端服务 active 冒充端到端完成。

禁止读取、生成、回显或保存密码、验证码、Tailscale Auth Key、授权 URL、Cookie、SSH 私钥、公钥正文、IP、邮箱、设备 ID、Host Key、OpenClaw/Kimi token、credentials 或环境变量值。授权 URL 可以由 tailscale up 在当前私有 Terminal 中显示一次，但不得写文件或加入最终摘要。

先只读预检；未全部通过不得改系统：
1. 验证 ADMIN_USER 和 NODE_NAME 格式。
2. 当前为 root，或 sudo -n true 成功；不得触发密码提示。
3. 当前是受支持的 Linux，systemd 为 PID 1，且 systemctl 可用。
4. /dev/net/tun 可用。
5. 能通过 HTTPS 访问 Tailscale 官方安装源。
6. Kimi Web Terminal 仍可作为恢复入口。
7. 记录 tailscaled 和传统 OpenSSH 当前状态；不得改变 OpenSSH 状态。

若缺少 root/免密 sudo、systemd、TUN 或出站 HTTPS，立即停止。不要改用 userspace networking，不要开放公网端口，不要做猜测性修复。

预检通过后执行最小、幂等变更：
1. 若 ADMIN_USER 不存在，非交互创建 home 与登录 shell，并锁定本地密码。创建独立 NOPASSWD sudoers 片段时，先对临时文件执行 visudo -cf，通过后才原子安装；随后以该用户验证 sudo -n true。失败时撤销本次创建的用户和片段并停止。
2. 若 ADMIN_USER 已存在，不修改其密码或权限；只验证以该用户执行 sudo -n true。失败时 ADMIN_SUDO=unavailable，OVERALL=incomplete。
3. 按实际发行版使用 Tailscale 官方 Linux 安装方法，不把某个发行版的软件源硬套到其他系统。
4. enable --now tailscaled，并核验 active 和 enabled。
5. 若节点未加入 Tailnet，运行 tailscale up，hostname 使用 NODE_NAME，并固定 --accept-dns=false --accept-routes=false。
6. 若出现网页授权要求，让 URL 只显示在当前私有 Terminal，最终输出 AUTH_REQUIRED 后停止。由用户本人完成授权，再用相同环境变量和本 Prompt 重新运行。
7. 仅在节点确认 Running 后执行 tailscale set --ssh。
8. 不安装或修改 openssh-server，不修改防火墙、云入口规则、Tailnet Policy、系统 DNS 或默认路由；不配置 Funnel、Serve、Exit Node 或子网路由。
9. 不使用 StrictHostKeyChecking=no，不执行 tailscale up --force-reauth。
10. 不执行 reboot、shutdown 或任何会中断当前恢复入口的操作。

服务器内部只验证 tailscaled active/enabled、节点 Online、Tailscale SSH 已启用以及 OpenSSH 状态未改变。服务器内部不能验证 Tailnet Policy、第二台设备 SSH、公网 TCP 22 不可达、设备 Key Expiry 或重启持久性。
